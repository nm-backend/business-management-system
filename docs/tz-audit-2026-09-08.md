# Аудит соответствия ТЗ — SkladPro.Nod

Дата: 2026-09-08. Метод: **ТЗ → функция → backend → API → permissions → frontend → тест**.
Статусы проставлены по факту прогона проверок, а не по чтению кода: каждая строка
таблицы имеет тест, который её подтверждает, либо явную пометку «не проверено».

Прогон на момент составления: **1240 backend-тестов, 74 frontend — все зелёные**;
миграции применяются на чистой БД и идемпотентны (`migrate` дважды → «No migrations to apply»).

---

## 0. Как проверялось

Ключевой инструмент — `apps/core/tests_tz_compliance_k.py` (50 сквозных проверок).
Он не читает код, а бьёт по живому API от лица каждой роли и **рекурсивно сканирует
ответы на денежные ключи**: точечная проверка отдельных полей пропускает утечку через
вложенный сериализатор, аннотацию или новый эндпоинт, а сканирование ловит её
автоматически, в том числе в будущем коде.

Дополнительно проверено вживую на поднятом сервере (sqlite-профиль песочницы):
вход тремя ролями, квартальный отчёт обоих видов, ставки труда, экспорт, bootstrap.

## Итог

Найдено и исправлено в этой итерации: **6 проблем**, из них 2 связаны с безопасностью
(публичный bootstrap, утечка ставок администратору), 2 — с отсутствующей
функциональностью ТЗ (квартальный отчёт администратора и эндпоинт квартала),
1 — бизнес-правило архива клиента, 1 — неверное поле в квартальной таблице интерфейса.

Ни один существующий тест не был ослаблен: изменены только два теста, чьё
поведение прямо противоречило ТЗ (экран входа и bootstrap), с объяснением в коде.
