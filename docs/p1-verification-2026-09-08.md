# Сверка после P1 — SkladPro.Nod

Цепочка проверки: **ТЗ → макет → DB → backend → API → permissions → frontend → tests**.
Прогон: **1393 теста на PostgreSQL 16.2** (2 пропуска), **1393 на SQLite** (66 пропусков —
PG-only сценарии гонок), **82 frontend**. Миграции применяются на чистой БД.

## P1-2. Документ прихода (GoodsReceipt)

| Звено | Состояние |
|---|---|
| ТЗ | «добавлять приход материала», «все изменения склада должны иметь историю» |
| Макет | Лист 1 «Материални қабул қилиш»: поставщик, номер, дата — один раз; позиции + «Яна материал қўшиш» |
| DB | `GoodsReceipt` (supplier, document_number, receipt_date, comment, created_by) + `GoodsReceiptLine` (material, quantity, price_per_unit) + `StockMovement.receipt`; уникальный частичный индекс по (company, supplier, document_number) при непустом номере; миграция `warehouse/0022` |
| Backend | `create_goods_receipt()` — одна транзакция на весь документ, использует существующий `record_incoming` (одна формула себестоимости) |
| API | `POST/GET /api/v1/warehouse/goods-receipts/`; PATCH и DELETE запрещены (405) |
| Permissions | Создание и чтение — E/A; W — 403. Цену принимает и видит **только E** (`GoodsReceiptNoMoneySerializer` убирает и цены строк, и итог) |
| Frontend | Кнопка «Материални қабул қилиш», форма с добавлением строк, цена только у владельца |
| Tests | 19, включая 2 конкурентных на PostgreSQL |

**Инварианты (все проверены тестами):**

| Требование этапа | Тест | Результат |
|---|---|---|
| Атомарное создание всех позиций | `test_receipt_applies_all_lines` | ✅ 3 позиции — 3 остатка |
| Нет частично созданного прихода | `test_bad_line_rolls_back_whole_document` | ✅ 0 документов, 0 движений после ошибки |
| Остатки меняются корректно | `test_average_cost_recalculated_like_single_incoming` | ✅ средневзвешенная как у одиночного прихода |
| История ссылается на операцию | `test_history_links_to_the_operation` | ✅ `StockMovement.receipt` у всех трёх |
| Компания позиции = tenant операции | `test_foreign_material_rolls_back_whole_document` | ✅ откат целиком |
| Повтор не создаёт двойной приход | `test_same_document_number_not_duplicated` | ✅ 400, остаток не удвоился |
| Concurrent requests | `test_parallel_identical_documents_apply_once`, `test_parallel_different_documents_sum_up` | ✅ ровно один 201; 4 разных = +40 |
| PostgreSQL | весь набор гоняется на PG | ✅ |
| Decimal | `test_decimal_precision_preserved` | ✅ 18.755 сохраняется точно |

**Найдено и исправлено по ходу:** уникальный индекс срабатывал, но API возвращал **500** вместо
бизнес-ошибки. Добавлен перехват `IntegrityError` в точке сохранения (вложенный `atomic` =
точка сохранения) — теперь 400 с понятным текстом, транзакция не рвётся.

## P1-4. Архив и группировка уведомлений

| Звено | Состояние |
|---|---|
| ТЗ | «удаление важных данных запрещено, только архивирование» |
| Макет | Лист 3: вкладки «Барчаси / Ўқилмаган / Архив», группы по смыслу |
| DB | `is_archived` (индекс) + `archived_at`; категория **не хранится** — выводится из типа; миграция `messaging/0018` |
| Backend | `Notification.archive()` идемпотентен; `types_for_category()` — единый источник истины |
| API | `?is_archived=true`, `?category=`, действие `POST .../archive/`, поле `category` в ответе |
| Permissions | Только свои уведомления; чужое архивировать нельзя |
| Frontend | Отдаётся API; вкладки — в P3 |
| Tests | 11 — прочитанное не теряется, архив не удаляет, повтор не переписывает дату, чужое недоступно |

**Найдено и исправлено:** фильтр по категории терял уведомления о подписке (их типов не было
в карте). Исправлено на модели, а не во вьюхе — чтобы источник истины остался один.
