# SkladPro.Nod — запуск с нуля (для нового разработчика)

Это пошаговое руководство для человека, который **никогда не работал с этим
проектом** и, возможно, впервые запускает Docker. Следуйте шагам по порядку —
в конце у вас будет полностью работающая ERP-система в браузере.

Проект запускается **одной командой** через Docker: Python, PostgreSQL и Redis
устанавливать вручную НЕ нужно.

## 1. Установка Docker Desktop

Docker — программа, которая запускает проект в изолированных «контейнерах».

- **Windows:** скачайте Docker Desktop с https://www.docker.com/products/docker-desktop
  Запустите установщик, соглашайтесь со значениями по умолчанию. При запросе
  включите **WSL 2** (Docker сам предложит). После установки — перезагрузите ПК.
- **macOS:** скачайте Docker Desktop (выберите чип Apple Silicon или Intel),
  перетащите в Applications, запустите.
- **Linux:** установите Docker Engine + Docker Compose plugin по инструкции
  https://docs.docker.com/engine/install/

Проверьте установку в терминале (Windows: PowerShell; macOS/Linux: Terminal):

```bash
docker --version
docker compose version
```

Обе команды должны показать номер версии.

---

## 2. Запуск Docker

Откройте приложение **Docker Desktop** и дождитесь, пока значок кита в трее
станет зелёным / статус будет **"Engine running"**. Пока Docker не запущен,
команды ниже работать не будут.

Проверка, что движок доступен:

```bash
docker info
```

Если видите строки про Server/ServerVersion — всё готово. Если ошибка
«Cannot connect to the Docker daemon» — Docker Desktop ещё не запустился.

## 4. Файл .env (необязательно)

**Для локального запуска через Docker `.env` создавать не обязательно** — в
`docker-compose.yml` уже заданы безопасные значения по умолчанию.

Если хотите изменить пароль БД или `SECRET_KEY`, скопируйте пример и отредактируйте:

```bash
# Windows PowerShell
copy .env.docker.example .env
# macOS/Linux
cp .env.docker.example .env
```

Внутри контейнеров базы данных и Redis адресуются по именам сервисов
(`db`, `redis`) — их менять не нужно.

## 5. Первый запуск

Из папки проекта выполните **одну команду**:

```bash
docker compose up --build
```

Что произойдёт автоматически:
- скачаются образы PostgreSQL и Redis;
- соберётся образ приложения (Python + зависимости);
- запустятся три контейнера: **web** (приложение), **db** (PostgreSQL), **redis**;
- применятся миграции базы данных;
- соберётся статика;
- запустится сервер на **http://localhost:8000**.

Первый запуск занимает несколько минут (скачивание и сборка). Когда увидите в
логах строку вида `Listening on TCP address 0.0.0.0:8000` — сервер готов.

> Совет: чтобы сервер работал в фоне, добавьте `-d`:
> `docker compose up --build -d`. Логи потом: `docker compose logs -f web`.

Откройте в браузере: **http://localhost:8000** — увидите страницу входа.

## 6. Миграции

Миграции применяются **автоматически** при каждом старте контейнера `web`
(это делает `docker/entrypoint.sh`). Отдельно запускать ничего не нужно.

Если всё же нужно применить их вручную (например, после обновления):

```bash
docker compose exec web python manage.py migrate
```

## 7. Создание супер-администратора

Супер-администратор — платформенный владелец (управляет всеми компаниями через
Django Admin). Создайте его один раз:

```bash
docker compose exec web python manage.py createsuperuser
```

Введите имя пользователя, email (можно пустой) и пароль (минимум 8 символов,
не слишком простой).

---

## 8. Открываем Django Admin

Откройте **http://localhost:8000/admin/** и войдите под супер-администратором.

Django Admin здесь — это **панель управления всей ERP**: компании, сотрудники,
навыки, Access Key, склад, заказы, финансы, чат, уведомления.

## 9. Компания → владелец → сотрудник → Access Key

Публичной регистрации нет. Аккаунты создаются внутри системы. Полный путь:

**9.1. Создать компанию (и её владельца за один шаг)**
1. В админке откройте **Companies → Add company**.
2. Заполните название и данные владельца (логин, пароль, ФИО).
3. Сохраните. Компания и её владелец (**Owner**) созданы.

**9.2. Создать сотрудника**
Сотрудников обычно заводит владелец в самом приложении (не в Django Admin), но
супер-админ тоже может создать их в **Accounts → Users → Add**: укажите
компанию, роль (`admin`/`worker`), ФИО. Пароль можно **не задавать** — сотрудник
задаст его сам при активации.

**9.3. Сгенерировать Access Key**
- В списке **Accounts → Users** отметьте нужных сотрудников галочкой и выберите
  действие **«Сгенерировать Access Key для выбранных сотрудников» → Go**;
- либо откройте раздел **Accounts → Access keys**, чтобы увидеть все коды,
  их **статус** (Active / Used / Revoked / Expired) и действия
  **«Отозвать»** и **«Перевыпустить»**.

**9.4. Скопировать код**
Код имеет вид `SKP-XXXX-XXXX-XXXX`. Скопируйте его из колонки
**«КОД (КОПИРУЙТЕ)»** и передайте сотруднику.

> Владелец делает то же самое из приложения через API
> `POST /api/v1/accounts/users/{id}/access_key/` (кнопка в интерфейсе сотрудников).

## 10. Первый вход сотрудника по Access Key

1. Сотрудник открывает **http://localhost:8000/accounts/login/**.
2. Нажимает **«У меня есть код доступа»**.
3. Вводит `SKP-XXXX-XXXX-XXXX` → **Продолжить**. Система показывает его имя и компанию.
4. Задаёт свой пароль → **Активировать и войти**.
5. Готово: аккаунт активирован, сотрудник вошёл. Код становится
   **использованным** (повторно не сработает).

## 11. Swagger, ReDoc, Чат

- **Swagger UI** (интерактивная документация API): http://localhost:8000/api/v1/swagger/
- **ReDoc** (читаемая документация API): http://localhost:8000/api/v1/redoc/
- **Чат** (реальное время через WebSocket): войдите в приложение → раздел
  **«Хабарлар» → вкладка «Чат»**. Есть «Умумий чат» (общий) и личные диалоги.
  Сообщения приходят мгновенно (Redis + WebSocket).

## 12. Остановка, пересборка, обновление

**Остановить** (контейнеры останавливаются, данные сохраняются):
```bash
docker compose down
```

**Остановить и удалить данные** (чистый старт — база и файлы стираются):
```bash
docker compose down -v
```

**Запустить снова** (без пересборки):
```bash
docker compose up -d
```

**Пересобрать после изменения кода/зависимостей:**
```bash
docker compose up --build -d
```

**Обновить проект из репозитория:**
```bash
git pull
docker compose pull      # обновить базовые образы (postgres, redis)
docker compose build     # пересобрать образ приложения
docker compose up -d     # перезапустить
docker compose exec web python manage.py migrate   # если появились миграции
```

**Полезные команды:**
```bash
docker compose ps                 # статус контейнеров
docker compose logs -f web        # логи приложения
docker compose exec web sh        # shell внутри контейнера
docker compose exec web python manage.py test   # запустить тесты
```

## 13. Частые проблемы и troubleshooting

| Проблема | Причина / Решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен. Откройте его и дождитесь «Engine running». |
| `port is already allocated` / порт 8000 занят | Другой процесс слушает 8000. Остановите его или поменяйте порт в `docker-compose.yml` (`"8001:8000"`), затем `docker compose up -d`. |
| Веб-контейнер перезапускается / падает | Смотрите причину: `docker compose logs web`. Часто это ошибка в `.env` или недоступная БД. |
| `database "skladpro_db" does not exist` / ошибки БД после смены имён | Пересоздайте тома: `docker compose down -v && docker compose up --build`. **Внимание: сотрёт данные.** |
| Долгая первая сборка | Это нормально (скачивание образов и установка зависимостей). Последующие запуски быстрые за счёт кэша. |
| Изменил код, но ничего не поменялось | Код примонтирован в контейнер, но сервер нужно перезапустить: `docker compose restart web`. |
| Не открывается админка/статика без стилей | Статику собирает entrypoint (`collectstatic`). Перезапустите: `docker compose restart web`. |
| Чат не обновляется в реальном времени | Проверьте, что контейнер `redis` в статусе healthy: `docker compose ps`. |
| Забыли пароль супер-админа | `docker compose exec web python manage.py changepassword <username>` |
| Хочу всё начать заново | `docker compose down -v` (удалит контейнеры и данные), затем `docker compose up --build`. |

Если что-то не получилось — скопируйте вывод `docker compose logs web` и покажите
разработчику: там почти всегда видно точную причину.
